# Документация к проекту «GophKeeper»

## 1. Введение

- Цель документа: описать архитектуру, требования и правила работы с проектом;
- Назначение проекта: для безопасного хранения логинов, паролей, бинарных данных и прочей приватной информации;
- Аудитория: студенты и пенсионеры, ваш брат, сын и бабушка;

## 2. Обзор проекта

Краткое описание: система позволяет создавать, назначать и отслеживать задачи.

Ключевые возможности:
- регистрация, аутентификация и авторизация пользователей;
- хранение приватных данных;
- передача приватных данных владельцу по запросу;

## 3. Требования
### 3.1 Функциональные требования

- Пользователь может зарегистрироваться;
- Авторизация должно происходить посредством выдачи и предоставления токена;
- После авторизации пользователь может отправлять на хранение обозначенную приватную информацию;
- Взаимодействие с севрисом долно осуществляться посредством клиента;
- Клиент должен распространяться в виде CLI-приложения с возможностью запуска на платформах Windows, Linux и Mac OS;
- Клиент должен давать пользователю возможность получить информацию о версии и дате сборки бинарного файла клиент;

### 3.2 Типы хранимой информации

- Пары логин/пароль;
- Произвольные текстовые данные;
- Произвольные бинарные данные;
- Данные банковских карт

## 4. Архитектура
- Тип: клиент‑серверная
- Компоненты:
  * Backend: Go
  * протокол взаимодействия с клиентом: HTTP + gRPC
  * База данных: PostgreSQL

## 5. Установка и запуск
5.1 Требования к окружению

5.1 Локальный запуск
- Склонировать репозиторий
- Установить зависимости: go mod tidy
- Запуск серверной части - make run
- Создание бинарного файла клиента - make build

## 6. Конфигурация
Основные переменные окружения:
- SERVER_ADDRESS_HTTP
- SERVER_ADDRESS_GRPC
- BASE_URL_HTTP
- BASE_URL_GRPC
- DATABASE_DSN
- JWT_SECRET

## 7. API (пример)
- HTTP-протокол:
  * После запуска проекта Swagger UI доступен по адресу: <http://localhost:8080/swagger/*>
  * Документация генерируется автоматически на основе аннотаций в коде backend‑приложения.

## 8. Поддержка и развитие
Планируемые улучшения:
- Реализация более продвинутого TUI для взамодействия с пользователем;
- Поддержка данных типа OTP (one time password);
